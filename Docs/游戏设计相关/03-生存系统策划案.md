## 一、项目概述

### 1.1 系统简介

生存系统是《沧海余生》的基础约束层，以「补给+耐久」双指标为核心，辅以体力行动资源，通过环境修正层提供丰富度，归零不致死仅降效，为中轻度泛用户提供有压力但不挫败的生存体验。

### 1.2 设计背景

游戏定位为中轻度泛用户优先，生存系统作为约束层而非核心玩法，需要提供生存压力感但不构成挫败来源。双指标极简设计降低管理负担，环境修正层在不变更指标数量的前提下提供丰富度。体力系统作为行动资源与时间消耗型指标解耦，让玩家明确区分"活得好不好"（补给/耐久）和"能干几件事"（体力）两条线。

### 1.3 核心循环定位

生存系统贯穿核心循环全程：

- **探索**消耗补给和体力
- **收集**恢复补给（拾荒、捕鱼、食物加工）
- **扩建**消耗耐久（建造施工损耗）
- **战斗**消耗耐久和体力（每次行动固定消耗体力）
- **成长**降低生存压力（更多设施 = 更多自动恢复路径）

### 1.4 关键设计决策摘要

| 序号 | 决策项 | 决策结果 | 决策依据 |
| :---: | --- | --- | --- |
| 1 | 生存指标数量 | 双指标（补给+耐久） | 泛用户门槛，5指标过重 |
| 2 | 致死设计 | 归零不致死，仅降效 | 避免挫败感 |
| 3 | 体力定位 | 行动资源，非生存指标 | 与时间消耗型指标解耦 |
| 4 | 环境修正叠加 | 加法叠加（方案A） | 可预测，防数值膨胀 |
| 5 | 天气系统归属 | 独立系统，后续单独编号 | 多系统共享天气状态 |
| 6 | 体力恢复与补给关系 | 无关联 | 明确排除交叉影响 |
| 7 | 体力离线恢复 | 配置控制，默认待定 | 预留灵活性 |
| 8 | 体力数值管理 | 全部走配置读取，不硬编码 | 预留扩展字段 |
| 9 | 厨房功能定位 | 厨房仅生产食物（烤鱼），不自动恢复补给 | 避免补给双重增长数值崩坏 |

## 二、设计目标分析

### 2.1 目标用户分析

| 用户画像 | 占比预估 | 生存系统关注点 | 设计应对 |
| --- | :---: | --- | --- |
| 休闲泛用户 | 60% | 不想被生存指标烦扰，希望自动运转 | 设施自动恢复路径，归零不致死 |
| 中度策略用户 | 30% | 享受资源管理博弈，追求效率最优 | 环境修正叠加策略，设施取舍博弈 |
| 硬核生存用户 | 10% | 想要生存压力和紧张感 | 极端环境修正组合，无设施时手动维护 |

### 2.2 体验目标

| 目标层级 | 目标描述 | 验证方式 |
| --- | --- | --- |
| 即时体验 | 玩家一眼看懂2根条+1个数字，知道现在该做什么 | 新手测试30分钟教程后问卷 |
| 短期留存 | 日常上线30分钟能维持指标正收益，不焦虑 | 日均补给/耐久净结余数据埋点 |
| 长期留存 | 随着设施完善，生存压力自然降低，转向探索和战斗 | 第7天/第30天生存指标均值追踪 |

| 指标 | 目标值 | 测量方式 | 备注 |
| --- | --- | --- | --- |
| 新手30分钟教程后指标理解率 | ≥ 90% | 课后问卷"是否理解补给和耐久的作用" | - |

## 三、系统规则

> 本板块是策划核心产出，描述系统的全部玩法逻辑与规则。
> 每个子模块独立编号，程序规则和数据表结构与之对应。

### 3.1 设计原则与定位

#### 3.1.1 核心设计哲学

**规则描述**：
生存系统是游戏的基础约束层，不是惩罚层。它的作用是给玩家的探索、建造、战斗行为提供资源消耗压力，让"收集资源"这件事有意义。生存系统不直接制造死亡威胁，而是通过效率降低来提示玩家"该补给/修船了"。

**三条设计原则**：

- **归零不致死**：任何指标归零都不会导致游戏结束，只会降低效率或限制行动
- **反馈直观**：每项指标有且仅有一个核心作用，玩家一眼就知道缺什么
- **恢复路径明确**：每项指标有 2-3 条恢复路径，不会出现"不知道怎么恢复"的情况

**不做士气系统**：不强制玩家"保持快乐"。想当战斗狂就只建炮台，想当商人就一直跑贸易，游戏不对玩家的玩法偏好做评判。

---

### 3.2 核心生存指标

#### 3.2.1 补给指标

**规则描述**：
补给是玩家维持船员生命运转的核心指标，代表食物和淡水的综合供给状态。补给随时间持续消耗，需要通过进食、被动休整恢复、伙伴技能三条路径恢复。

**规则细则**：

- 补给上限固定为 100，不可通过升级提升
- 在线状态下每分钟消耗 1 点补给
- 离线状态下每分钟消耗 0.3 点补给
- 补给值 ≤ 25 时触发低阈值警告
- 补给值归零（= 0）时，所有手动操作效率降低 50%
- 补给归零不影响离线收益（基础物资照发），但设施生产停摆
- 补给归零不影响体力恢复速度

**边界条件**：

| 条件 | 处理方式 |
| --- | --- |
| 补给值超过上限 100 | 截断至 100，溢出部分不返还 |
| 补给值低于 0 | 截断至 0，不出现负值 |
| 同时食用多种食物 | 按食用顺序依次结算，每次结算后检查是否溢出 |
| 补给归零时上线 | 立即触发归零惩罚状态，显示引导提示 |

**示例**：

> 玩家补给值为 35/100，处于夜晚（环境修正+0.2），当前海域为寒冷海域（修正+0.3）。
> 基础消耗速率为 1.0/分钟。
> 实际消耗 = 1.0 × (1 + 0.2 + 0.3) = 1.5/分钟。
> 35 点补给可维持约 23 分钟。

---

#### 3.2.2 耐久指标

**规则描述**：
耐久是玩家船体的结构完整性指标，代表船只的物理健康状态。耐久通过事件触发消耗（战斗、风暴、碰撞），需要通过手动修复、设施自动修复、伙伴技能三条路径恢复。

**规则细则**：

- 耐久上限固定为 100，不可通过升级提升
- 在线状态下自然损耗 0.5/小时（极低，主要是事件消耗）
- 离线状态下耐久不自然损耗（离线无战斗无风暴）
- 耐久值 ≤ 30 时触发低阈值警告
- 耐久值归零（= 0）时，航行速度降低 40%，无法进入战斗
- 耐久归零不影响探索移动（可以逃跑但不能主动战斗）
- 耐久归零不影响补给消耗和体力恢复

**耐久消耗来源**：

| 消耗来源 | 数值 | 频率 |
| --- | :---: | --- |
| 在线自然损耗 | -0.5/小时 | 持续 |
| 风暴遭遇 | -15 \~ -25 | 随机 |
| Boss 战斗（每场） | -10 \~ -30 | 按遭遇频率 |
| 巡游威胁（无视时） | -5 | 每 15-30 分钟 |

**边界条件**：

| 条件 | 处理方式 |
| --- | --- |
| 耐久值超过上限 100 | 截断至 100，溢出部分不返还 |
| 耐久值低于 0 | 截断至 0，不出现负值 |
| 耐久归零时遭遇战斗 | 强制逃跑，不可主动进入战斗 |
| 耐久归零时遭遇风暴 | 额外触发紧急事件"船体破损"，需手动修复至 ≥ 10 才能恢复航行 |

**示例**：

> 玩家耐久值为 50/100，遭遇一场 Boss 战斗消耗 30 点。
> 战斗后耐久 = 50 - 30 = 20/100，低于警告线 30，触发低阈值警告。
> 维修站自动修复 +3/分钟，约 3.3 分钟后耐久恢复至 30 以上，警告解除。

### 3.3 体力系统

#### 3.3.1 体力定位

**规则描述**：
体力是玩家的行动资源，**不是生存指标**。补给和耐久管"活得好不好"，体力管"能干几件事"，两条线独立运作。探索按行动次数消耗体力；战斗在进入战斗前一次性扣除体力，战斗回合内不再扣除。体力随时间自然恢复，与补给状态无关。

**核心区别**：

|   | 补给 | 耐久 | 体力 |
| --- | --- | --- | --- |
| **性质** | 生存指标 | 生存指标 | 行动资源 |
| **消耗方式** | 随时间持续消耗 | 事件触发消耗 | 按行动次数消耗 |
| **归零效果** | 手动操作效率 -50% | 航速 -40%，无法战斗 | 无法行动（不能探索/战斗） |
| **恢复方式** | 食物/设施/伙伴 | 材料/设施/伙伴 | 时间自然恢复 |
| **是否致死** | 不致死 | 不致死 | 不致死，仅限行动 |
| **与补给关系** | - | - | 无关联 |

---

#### 3.3.2 体力消耗规则

**规则描述**：
每次探索行动消耗固定体力值；进入一场战斗前同样消耗一次固定体力值。战斗内的回合、普通攻击和技能均不再消耗体力，避免战斗中途因体力归零导致无法完成当前战斗。

**规则细则**：

- 每次探索行动消耗 1 点体力（配置值，可调）
- 每次进入战斗消耗 1 点体力（配置值，可调）
- 探索与战斗的体力消耗值可以配置为不同值，但默认相同
- 体力归零时无法发起探索和战斗
- 体力归零不影响在线其他操作（建造、采集、管理设施等）
- 体力消耗不受环境修正影响（环境修正只作用于补给和耐久）

**边界条件**：

| 条件 | 处理方式 |
| --- | --- |
| 体力不足以发起行动 | 阻止行动，弹出"体力不足"提示，显示恢复倒计时 |
| 体力归零时正在探索中途 | 允许完成当前探索，返回后不可再次出发 |
| 战斗进行中 | 不再扣除体力；无论当前体力显示为何值，均允许完成该场战斗 |

---

#### 3.3.3 体力恢复规则

**规则描述**：
体力随时间自然恢复，恢复速度为每 15 分钟恢复 1 点（配置值，可调）。恢复与补给状态无关——即使补给归零，体力恢复速度不变。离线期间是否恢复体力由配置开关控制。

**规则细则**：

- 体力恢复速度：1 点 / 15 分钟（配置值）
- 体力恢复与补给值无关，明确排除交叉影响
- 体力恢复不受环境修正影响
- 离线期间体力是否恢复：由配置开关控制（`stamina_config.offline_recovery`）
- 体力恢复至上限时停止恢复，不溢出
- 体力恢复按经过时间累计结算，不要求连续在线

**示例**：

> 玩家体力上限为 10，当前体力为 3。
> 恢复至满体力需要 (10 - 3) × 15 = 105 分钟 = 1 小时 45 分钟。
> 若玩家离线 1 小时后上线，且离线恢复开关开启：
> 离线恢复体力 = floor(60 / 15) = 4 点，上线后体力 = 3 + 4 = 7（未超上限）。

### 3.4 环境修正系统

#### 3.4.1 修正源类型

**规则描述**：
环境修正是生存系统的丰富度层，在不增加指标条数量的前提下，通过改变消耗速率来体现昼夜、天气、海域温度等环境因素对生存的影响。当前阶段环境修正只作用于补给；耐久修正接口保留，但天气影响暂不启用；体力不受环境修正影响。

**四类修正源**：

| 修正源 | 影响指标 | 修正系数范围 | 触发条件 | 归属系统 |
| --- | :---: | :---: | --- | --- |
| 昼夜修正 | 补给 | +0.0 \~ +0.2 | 夜晚时段（18:00-06:00 游戏内时间） | 生存系统（内部） |
| 天气修正 | 补给、耐久（预留） | +0.0 \~ +0.5 | 暴雨/台风/海雾/酷暑等天气激活时 | 天气系统（独立，当前不启用） |
| 海域温度修正 | 补给 | +0.0 \~ +0.3 | 当前所在海域的温度属性 | 探索系统 |
| 行动消耗修正 | 补给 | +0.0 \~ +0.5 | 战斗/探索行动后额外扣减 | 生存系统（内部） |

---

#### 3.4.2 叠加规则

**规则描述**：
多个环境修正同时生效时，采用**加法叠加**（方案A）。所有生效修正系数相加后，乘以基础消耗速率，得到实际消耗速率。

**叠加公式**：

```
实际消耗速率 = 基础消耗速率 × (1 + 修正系数A + 修正系数B + 修正系数C + ...)
```

**规则细则**：

- 加法叠加，不做乘法
- 修正系数之和有上限保护，最高不超过 +2.0（即实际消耗最多为基础的 3 倍）
- 超过上限时截断至 +2.0
- 同类修正源不重复叠加（如两个天气修正同时生效时取较大值，不累加）
- 不同类修正源之间正常累加（昼夜 + 天气 + 海域温度 + 行动消耗）

**边界条件**：

| 条件 | 处理方式 |
| --- | --- |
| 修正系数之和 \> 2.0 | 截断至 2.0 |
| 同类修正源多个同时生效 | 取最大值，不累加 |
| 修正源被移除（如天气结束） | 立即从修正系数之和扣除，重新计算实际消耗速率 |
| 基础消耗速率为 0（如离线耐久） | 修正系数不生效，实际消耗仍为 0 |

**示例**：

> 夜晚（修正+0.2）+ 暴雨天气（修正+0.3）+ 寒冷海域（修正+0.3）同时生效。
> 修正系数之和 = 0.2 + 0.3 + 0.3 = 0.8（未超上限 2.0）。
> 补给基础消耗 = 1.0/分钟。
> 实际消耗 = 1.0 × (1 + 0.8) = 1.8/分钟。
>
> 若同时还有行动消耗修正 +0.5：
> 修正系数之和 = 0.2 + 0.3 + 0.3 + 0.5 = 1.3（未超上限）。
> 实际消耗 = 1.0 × (1 + 1.3) = 2.3/分钟。

---

#### 3.4.3 昼夜修正细则

**规则描述**：
游戏内时间分为白天和夜晚两个时段。夜晚时段补给消耗速率增加，海上威胁活性增强。

**规则细则**：

- 白天（06:00-18:00 游戏内时间）：修正系数 = 0.0
- 夜晚（18:00-次日06:00 游戏内时间）：修正系数 = +0.2
- 游戏内 1 天 = 现实 30 分钟（白天 15 分钟，夜晚 15 分钟）
- 昼夜修正只影响补给消耗，不影响耐久
- 昼夜修正不受天气和海域影响，是独立的基础修正

---

#### 3.4.4 天气修正细则

**规则描述**：
天气系统是独立系统（后续单独编号）。当前 MVP 仅保留天气数据与接口，不对补给或耐久结算施加影响；天气效果启用时，统一采用本章的加法修正规则，不再使用额外乘法倍率。

**天气对生存的影响映射**：

| 天气类型 | 补给修正 | 耐久修正 | 持续时间 | 备注 |
| --- | :---: | :---: | --- | --- |
| 晴天 | 0.0 | 0.0 | - | 无影响 |
| 暴雨 | +0.2 | +0.3 | 5-10 分钟 | 视野略受影响 |
| 台风 | +0.3 | +0.5 | 3-5 分钟 | 航速降低，高威胁 |
| 海雾 | +0.1 | 0.0 | 5-15 分钟 | 探索视野受限 |
| 酷暑 | +0.3 | 0.0 | 5-10 分钟 | 补给消耗加剧 |

> *备注：天气的具体触发逻辑、切换规则、持续时间由天气系统独立设计。表中数值是后续启用时的配置预留，当前结算按 0.0 处理。*

---

#### 3.4.5 海域温度修正细则

**规则描述**：
不同海域有不同的温度属性，影响补给消耗速率。海域温度在探索系统中定义，生存系统引用其修正系数。

**海域温度修正表**：

| 海域类型 | 补给修正 | 备注 |
| --- | :---: | --- |
| 温带海域 | 0.0 | 默认海域，无修正 |
| 寒冷海域 | +0.3 | 补给消耗加剧 |
| 炎热海域 | +0.2 | 补给消耗略增 |
| 极地海域 | +0.5 | 极端环境，高消耗 |

> *备注：海域类型归属探索系统定义，此处仅引用其修正系数。*

---

#### 3.4.6 行动消耗修正细则

**规则描述**：
玩家执行探索或战斗行动后，除消耗体力外，还会额外扣减补给。这是对"体力"概念的替代——不增加独立指标，但让行动有生存成本。

**规则细则**：

- 探索行动完成后：额外扣减补给（配置值，默认待定）
- 进入战斗时：额外扣减补给（配置值，默认待定）
- 行动消耗修正是即时扣减，不是持续修正
- 扣减后若补给低于 0，截断至 0
- 行动消耗修正不影响耐久
- 行动消耗修正不与环境修正叠加计算（是独立的即时扣减，不进入加法叠加公式）

**与加法叠加的区别**：

- 环境修正（昼夜/天气/海域温度）：持续修正，改变消耗速率，进入加法叠加公式
- 行动消耗修正：即时扣减，不改变消耗速率，不进入加法叠加公式

> *备注：此处行动消耗修正在 3.4.1 修正源类型表中列出是为了完整性说明，但在程序实现中它是一个独立的即时扣减事件，不参与环境修正的加法叠加计算。*

### 3.5 补给物资体系

#### 3.5.1 食物种类

**规则描述**：
补给通过消耗食物恢复。共有 4 种食物，恢复量、获取方式、储存上限各不相同。

**食物配置表**：

| 物资 | 恢复量 | 获取方式 | 生产耗时 | 来源设施 | 储存上限（无设施） | 储存上限（有设施） |
| --- | :---: | --- | :---: | --- | :---: | :---: |
| 烤鱼 | +15 | 厨房烹饪（生鱼×1） | 20 秒 | 厨房 | 10 | 30（有冰箱） |
| 淡水 | +10 | 蒸馏器生产（海水×1） | 30 秒 | 蒸馏器 | 20 | 50（有储水罐） |
| 罐头 | +20 | 探索拾取 | - | 无（仅探索获取） | 15 | 40（有冰箱） |
| 果酒 | +20 | 酿造器生产（水果×2） | 90 秒 | 酿造器 | 5 | 20（有酒窖） |

**规则细则**：

- 食物消耗是手动操作，玩家点击食物图标使用
- 同时只能使用 1 种食物，使用后进入 1 秒冷却（防误触）
- 食物储存上限受设施影响：有对应储存设施时上限提升
- 食物储存达到上限时，多余产出溢出消失（不自动使用）
- 罐头只能通过探索拾取，不可生产

**效率对比**：

| 设施组合 | 每分钟产出 | 可恢复补给/分钟（手动食用） | 占地 |
| --- | :---: | :---: | :---: |
| 厨房 | 3 烤鱼 | 3 × 15 = 45 补给/分钟（手动） | 2 格 |
| 蒸馏器 | 2 淡水 | 2 × 10 = 20 补给/分钟（手动） | 2 格 |
| 厨房 + 蒸馏器 | — | 65 补给/分钟（手动） | 4 格 |

> 4 格生存设施 = 远超在线基础消耗的食物产能。但食物需玩家**手动食用**，不是自动恢复。配合被动休整恢复（+0.5/分钟在线自动），形成"被动兜底 + 主动补充"的双层恢复体系。溢出产能用于离线消耗和探索移动前的补给储备。

### 3.6 恢复机制

#### 3.6.1 三条恢复路径

**规则描述**：
补给和耐久各有 3 条恢复路径，确保玩家在任何情况下都有恢复手段。

**补给恢复路径**：

| 路径 | 恢复方式 | 恢复量 | 触发方式 | 备注 |
| :---: | --- | :---: | --- | --- |
| 1 | 手动消耗食物 | +10 \~ +20/次 | 玩家点击使用 | 需有库存 |
| 2 | 被动休整恢复 | +0.5/分钟 | 在线时持续生效 | 无需任何设施，船员自然休息 |
| 3 | 伙伴技能"野外觅食" | 战斗后掉落补给包 | 伙伴出战时被动 | 需有对应伙伴 |

**耐久恢复路径**：

| 路径 | 恢复方式 | 恢复量 | 触发方式 | 备注 |
| :---: | --- | :---: | --- | --- |
| 1 | 手动消耗材料修复 | +20/次 | 玩家点击修复 | 需消耗木材/金属 |
| 2 | 维修站设施自动修复 | +3/分钟 | 设施运转时持续 | 需有材料库存 |
| 3 | 伙伴技能"巧手修复" | 战斗后自动回复耐久 | 伙伴出战时被动 | 需有对应伙伴 |

---

#### 3.6.2 设施自动恢复规则

**规则描述**：
维修站是唯一具备自动恢复功能的设施，在运转期间持续自动修复耐久，无需玩家手动操作。厨房和蒸馏器仅负责生产食物（供玩家手动食用），不具备自动恢复补给功能。被动休整恢复作为所有玩家在线的持续基础恢复手段，无需依赖任何设施。

**规则细则**：

- **维修站自动修复**：每分钟消耗少量材料（木材×1），恢复 +3/分钟耐久
- **厨房**：每 20 秒消耗 1 生鱼，产出 1 烤鱼（自动存入仓库）——**仅生产食物，不自动恢复补给**
- **蒸馏器**：每 30 秒消耗 1 海水，产出 1 淡水——**仅生产淡水，不自动恢复补给**
- 设施原料不足时停摆，不恢复指标/不产出食物，需玩家补充原料
- 设施自动恢复不会使指标超过上限
- 离线时所有设施停摆（不消耗原料，不恢复指标，不产出食物），离线收益由离线挂机系统单独处理

#### 3.6.3 被动休整恢复

**规则描述**：
被动休整是船员自然休息带来的基础补给恢复，在线期间持续生效，**不依赖任何设施**。它的定位是"安全网"——确保无设施的新手玩家也有基础生存兜底，不会"什么都不建就绝望"。被动休整效率远低于手动进食（+0.5/分钟 vs +10\~20/次），无法单独覆盖基础消耗，必须配合食物或设施才能维持正收益。

**规则细则**：

- 恢复速率：+0.5/分钟（在线持续生效）
- 触发条件：玩家在线时自动生效，无需任何设施
- 离线时：被动休整**停摆**（离线不生效果）
- 与补给消耗对比：无设施时净结余 = 基础消耗(1.0) - 被动休整(0.5) = -0.5/分钟（慢速下降）
- 不参与环境修正：被动休整速率为固定值，不受天气/昼夜/海域修正影响
- 上限保护：补给已满时停止恢复，不溢出

**效率对比**：

| 恢复手段 | 效率 | 触发方式 | 依赖 |
| --- | :---: | --- | --- |
| 手动进食（烤鱼） | +15/次 | 手动 | 需厨房产出食物 |
| 被动休整 | +0.5/分钟 | 在线自动 | 无需任何设施 |
| 伙伴技能 | 战斗后掉落 | 被动 | 需对应伙伴出战 |

---

### 3.7 归零保护机制

#### 3.7.1 归零惩罚

**规则描述**：
指标归零时不致死，仅施加效率惩罚。惩罚设计为"不便但不绝望"，引导玩家恢复而非惩罚玩家。

**归零惩罚表**：

| 指标 | 归零效果 | 持续时间 | 恢复条件 |
| --- | --- | --- | --- |
| 补给归零 | 所有手动操作效率 -50%（建造耗时翻倍、采集产出减半） | 持续至补给恢复 \> 0 | 进食或等待被动休整恢复 |
| 耐久归零 | 航速 -40%，无法进入战斗 | 持续至耐久恢复 \> 0 | 手动修复或等待维修站自动恢复 |
| 体力归零 | 无法发起探索和战斗 | 持续至体力恢复 ≥ 1 | 等待时间自然恢复 |

---

#### 3.7.2 自动拉回机制

**规则描述**：
当指标归零时，系统通过加速恢复帮助玩家快速脱离归零状态。这是安全网设计，防止玩家因忘记管理而长时间处于惩罚状态。

**规则细则**：

- 补给归零时：被动休整恢复效率临时提升至 ×3（+1.5/分钟），持续至补给 ≥ 10。**不需任何设施支持，所有玩家通用。**
- 耐久归零且有维修站运转时：维修站恢复效率临时提升至 ×2（+6/分钟），持续至耐久 ≥ 10
- 设施加速运转不额外消耗原料
- 若无维修站，不触发耐久自动拉回，需玩家手动修复
- 体力归零不触发自动拉回（体力恢复仅靠时间）

### 3.8 低阈值警告机制

#### 3.8.1 警告触发

**规则描述**：
当指标低于警告阈值时，系统通过视觉、音效和引导提示三层反馈提醒玩家。

**警告阈值表**：

| 指标 | 警告阈值 | 触发条件 |
| --- | :---: | --- |
| 补给 | ≤ 25 | 补给值降至 25 及以下 |
| 耐久 | ≤ 30 | 耐久值降至 30 及以下 |
| 体力 | ≤ 2 | 体力值降至 2 及以下 |

---

#### 3.8.2 警告表现

**三层警告反馈**：

| 层级 | 触发条件 | 表现形式 | 持续时间 |
| :---: | --- | --- | --- |
| 视觉 | 指标 ≤ 警告阈值 | 指标条颜色变为橙色，边缘脉冲红光 | 持续至指标恢复 |
| 音效 | 指标 ≤ 警告阈值 | 低沉警告音（每 30 秒一次） | 持续至指标恢复 |
| 引导 | 指标 ≤ 警告阈值 | 指标条旁出现引导按钮"去恢复" | 持续至指标恢复 |

**规则细则**：

- 警告状态在指标恢复至阈值以上后立即解除
- 警告不会升级为强制弹窗（不打断玩家当前操作）
- 引导按钮点击后跳转至对应管理界面（补给→厨房/仓库，耐久→维修站）
- 体力警告不显示引导按钮（体力恢复只能等时间）

## 四、程序规则

### 4.1 指标 Tick 更新机制

#### 4.1.1 处理流程

**触发条件**：定时器 `SurvivalTick` 每 5 秒触发一次

**处理时序**：

```
[SurvivalTick 触发] → [读取玩家在线状态] → [计算环境修正系数之和] → [结算补给消耗] → [结算耐久消耗] → [结算体力恢复] → [检查阈值/归零状态变更] → [状态机更新] → [事件广播] → [UI 刷新]
```

**详细步骤**：

| 步骤 | 操作 | 数据变更 | 异常处理 |
| :---: | --- | --- | --- |
| 1 | 读取 `survival_status` 表获取当前指标值和在线状态 | 无 | 数据不存在时初始化为默认值 |
| 2 | 查询当前生效的环境修正源，计算修正系数之和 | 无 | 修正源数据缺失时按 0.0 处理 |
| 3 | 在线：结算补给消耗 = 基础消耗 × (1 + 修正系数之和) × (5/60) 分钟 | `supply -= 消耗值` | 补给 \< 0 截断至 0 |
| 4 | 在线：结算耐久消耗 = 基础损耗 × (1 + 耐久修正系数之和) × (5/3600) 小时；当前耐久修正系数之和固定为 0 | `durability -= 损耗值` | 耐久 \< 0 截断至 0 |
| 5 | 结算体力恢复 = floor(经过时间 / 恢复间隔) | `stamina += 恢复值` | 体力 \> 上限截断至上限 |
| 6 | 检查指标是否跨越阈值（正常→警告→归零） | 更新 `status` 字段 | 触发状态变更事件 |
| 7 | 广播指标更新事件 | 无 | UI 订阅者接收并刷新 |

---

#### 4.1.2 定时器配置

| 定时器名称 | 频率 | 用途 | 暂停条件 |
| --- | --- | --- | --- |
| `SurvivalTick` | 每 5 秒 | 在线指标消耗结算 | 玩家离线、游戏暂停 |
| `OfflineSettlement` | 上线时一次性 | 离线期间消耗结算 | 无（上线时触发） |
| `StaminaRecoverTick` | 随 SurvivalTick | 体力恢复结算 | 无（始终运行，含离线） |

> *备注：离线消耗不用循环定时器，而是在上线时用公式一次性结算。体力恢复在离线期间也累计，上线时一并结算（如果配置开关开启）。*

### 4.2 环境修正叠加计算

#### 4.2.1 处理流程

**触发条件**：`SurvivalTick` 每次执行时调用

**处理时序**：

```
[查询昼夜修正] → [查询天气修正] → [查询海域温度修正] → [同类取最大值] → [跨类加法求和] → [上限截断] → [输出修正系数之和]
```

**详细步骤**：

| 步骤 | 操作 | 数据变更 | 异常处理 |
| :---: | --- | --- | --- |
| 1 | 查询当前游戏内时间，判定昼夜，获取昼夜修正系数 | 无 | 时间数据异常时按白天处理（修正=0.0） |
| 2 | 查询天气系统当前激活的天气列表，获取天气修正系数 | 无 | 天气系统未响应时按晴天处理（修正=0.0） |
| 3 | 查询当前所在海域类型，获取海域温度修正系数 | 无 | 海域数据缺失时按温带处理（修正=0.0） |
| 4 | 同类修正源取最大值（如多个天气同时生效取最大） | 无 | - |
| 5 | 跨类修正系数加法求和 | 无 | - |
| 6 | 若修正系数之和 \> 2.0，截断至 2.0 | 无 | - |
| 7 | 输出修正系数之和 `modifier_sum` | 传给消耗结算模块 | - |

---

### 4.3 补给消耗与恢复结算

#### 4.3.1 在线消耗结算

**触发条件**：`SurvivalTick` 每 5 秒触发

**计算公式**：

```
supply_decrement = base_supply_rate × (1 + modifier_sum) × (tick_interval / 60)
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `supply_decrement` | float | 本次 Tick 补给减少量 | 计算得出 |
| `base_supply_rate` | float | 基础消耗速率（1.0/分钟） | 配置表读取 |
| `modifier_sum` | float | 环境修正系数之和 | 4.2 模块计算 |
| `tick_interval` | int | Tick 间隔秒数（5） | 配置表读取 |

---

#### 4.3.2 食物使用结算

**触发条件**：玩家点击食物使用

**处理时序**：

```
[玩家点击食物] → [校验库存 > 0] → [校验补给未满] → [扣减食物库存] → [增加补给值] → [检查溢出] → [UI刷新] → [1秒冷却]
```

**详细步骤**：

| 步骤 | 操作 | 数据变更 | 异常处理 |
| :---: | --- | --- | --- |
| 1 | 校验食物库存 | 无 | 库存 = 0 时提示"库存不足" |
| 2 | 校验补给值 \< 上限 | 无 | 补给已满时提示"补给已满" |
| 3 | 扣减食物库存 -1 | `food_inventory -= 1` | - |
| 4 | 增加补给值 +恢复量 | `supply += recovery_amount` | - |
| 5 | 检查补给是否溢出 | 若 `supply > 100` 则 `supply = 100` | - |
| 6 | 进入 1 秒冷却 | 设置冷却结束时间戳 | 冷却期间禁止再次使用食物 |

---

#### 4.3.3 设施自动产出结算

**触发条件**：`SurvivalTick` 每 5 秒触发

**厨房产出逻辑**：

```
每 20 秒厨房产出 1 烤鱼 → 每 5 秒 Tick 产出 0.25 烤鱼
累计产出 >= 1 时，实际入库 1 个，剩余小数保留
```

**规则**：

- 厨房产出按 20 秒周期计算，5 秒 Tick 产出 0.25 个
- 累计小数部分在内存中保留，达到 1.0 时实际入库
- 入库时检查储存上限，溢出部分消失
- 原料不足时停止产出，小数部分清零
- 厨房**仅产出食物，不自动恢复补给**——玩家需手动食用食物来恢复补给

#### 4.3.4 被动休整恢复结算

**触发条件**：`SurvivalTick` 每 5 秒触发（仅在线时生效）

**计算公式**：

```
passive_recovery = passive_recovery_rate × (tick_interval / 60) × acceleration_multiplier
supply += passive_recovery
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `passive_recovery` | float | 本次 Tick 被动休整恢复量 | 计算得出 |
| `passive_recovery_rate` | float | 基础恢复速率（0.5/分钟） | `survival_config` 读取 |
| `tick_interval` | int | Tick 间隔秒数（5） | 配置表读取 |
| `acceleration_multiplier` | float | 加速倍率（正常=1.0，归零加速=3.0） | 状态机判断 |

**规则**：

- 被动休整仅在线时生效，离线时停摆
- 补给已满时停止恢复（截断至上限 100）
- 归零加速倍率 = 3.0，持续至补给 ≥ 10，之后恢复正常倍率 1.0
- 归零加速不消耗任何资源

---

### 4.4 耐久损耗与修复结算

#### 4.4.1 事件损耗结算

**触发条件**：战斗结束、风暴遭遇、巡游威胁等事件

**处理时序**：

```
[事件触发] → [读取损耗值] → [扣减耐久] → [检查归零] → [状态机更新] → [事件广播]
```

**详细步骤**：

| 步骤 | 操作 | 数据变更 | 异常处理 |
| :---: | --- | --- | --- |
| 1 | 事件系统发送损耗事件，附带损耗值 | 无 | - |
| 2 | 扣减耐久值 | `durability -= loss_amount` | 耐久 \< 0 截断至 0 |
| 3 | 检查耐久是否归零 | 若 = 0 则触发归零惩罚 | - |
| 4 | 检查是否跨越警告阈值 | 若 ≤ 30 则触发警告 | - |
| 5 | 广播耐久更新事件 | 无 | UI 刷新 |

---

#### 4.4.2 手动修复结算

**触发条件**：玩家点击修复按钮

**处理时序**：

```
[玩家点击修复] → [校验材料库存] → [校验耐久未满] → [扣减材料] → [增加耐久] → [检查溢出] → [播放修复动画] → [UI刷新]
```

**详细步骤**：

| 步骤 | 操作 | 数据变更 | 异常处理 |
| :---: | --- | --- | --- |
| 1 | 校验木材/金属库存 ≥ 需求量 | 无 | 不足时提示"材料不足" |
| 2 | 校验耐久值 \< 上限 100 | 无 | 已满时提示"耐久已满" |
| 3 | 扣减材料 | `material -= cost` | - |
| 4 | 增加耐久 +20 | `durability += 20` | - |
| 5 | 检查溢出 | 若 \> 100 则 = 100 | - |
| 6 | 播放修复动画（1 秒） | 无 | - |

---

#### 4.4.3 维修站自动修复结算

**触发条件**：`SurvivalTick` 每 5 秒触发

**计算逻辑**：

```
维修站恢复速率 = +3/分钟
每 5 秒 Tick 恢复 = 3 × (5/60) = 0.25 耐久
```

**归零加速规则**（仅耐久）：

- 耐久 = 0 且维修站运转时：恢复速率临时 ×2 = +6/分钟
- 持续至耐久 ≥ 10 后恢复正常速率
- 加速期间不额外消耗材料

---

### 4.5 体力消耗与恢复结算

#### 4.5.1 行动消耗结算

**触发条件**：玩家发起一次探索，或确认进入一场战斗

**处理时序**：

```
[玩家发起探索 / 确认进入战斗] → [校验体力 ≥ 对应消耗] → [一次性扣减体力] → [执行探索 / 进入战斗] → [行动结算] → [补给额外扣减] → [UI刷新]
```

**详细步骤**：

| 步骤 | 操作 | 数据变更 | 异常处理 |
| :---: | --- | --- | --- |
| 1 | 探索读取 `cost_per_explore`；战斗读取 `cost_per_battle`，校验当前体力充足 | 无 | 不足时阻止探索或进入战斗，弹出恢复倒计时 |
| 2 | 一次性扣减对应体力 | `stamina -= action_cost` | 战斗扣除发生在 BattleSystem 创建 BattleState 前 |
| 3 | 执行探索逻辑或进入战斗 | 由探索/战斗系统处理 | 战斗回合内不再调用体力扣减 |
| 4 | 探索完成后或进入战斗时，额外扣减补给 | `supply -= action_supply_cost` | 补给 \< 0 截断至 0 |
| 5 | 广播体力更新事件 | 无 | UI 刷新 |

---

#### 4.5.2 体力恢复结算

**触发条件**：`SurvivalTick` 每 5 秒触发（在线）/ 上线时一次性结算（离线）

**在线恢复计算**：

```
recovery_points = floor(elapsed_seconds / (recovery_interval_min × 60))
stamina += recovery_points
```

**离线恢复计算**：

```
若 stamina_config.offline_recovery == true:
    offline_seconds = 上线时间 - 上次离线时间
    recovery_points = floor(offline_seconds / (recovery_interval_min × 60))
    stamina += recovery_points（截断至上限）
否则:
    不恢复
```

**规则**：

- 恢复量取整数（floor 向下取整）
- 恢复至上限时停止
- 离线恢复不扣除"未满效率时段"——只要离线恢复开关开启，离线期间全程恢复
- 体力恢复不受补给值影响（`recovery_supply_link` 固定为 false）

### 4.6 警告与状态变更

#### 4.6.1 状态机定义

**指标状态机（补给/耐久通用）**：

**状态列表**：

| 状态名 | 说明 | 可转换至 |
| --- | --- | --- |
| `STATE_NORMAL` | 正常状态（指标 \> 警告阈值） | `STATE_WARNING` |
| `STATE_WARNING` | 警告状态（指标 ≤ 警告阈值且 \> 0） | `STATE_NORMAL`, `STATE_DEPLETED` |
| `STATE_DEPLETED` | 归零状态（指标 = 0） | `STATE_RECOVERING` |
| `STATE_RECOVERING` | 恢复中状态（归零后恢复中，指标 \< 安全线） | `STATE_NORMAL` |

**状态转换条件**：

| 当前状态 | 转换条件 | 目标状态 | 副作用 |
| --- | --- | --- | --- |
| `STATE_NORMAL` | 指标值 ≤ 警告阈值 | `STATE_WARNING` | 触发警告UI（橙色条+脉冲红光+警告音） |
| `STATE_WARNING` | 指标值 \> 警告阈值 | `STATE_NORMAL` | 关闭警告UI |
| `STATE_WARNING` | 指标值 ≤ 0 | `STATE_DEPLETED` | 触发归零惩罚 + 灰化UI + 引导按钮 |
| `STATE_DEPLETED` | 指标值 \> 0（恢复中） | `STATE_RECOVERING` | 触发加速恢复（补给：被动休整×3无需设施；耐久：维修站×2如有设施） |
| `STATE_RECOVERING` | 指标值 ≥ 安全线（警告阈值 + 5） | `STATE_NORMAL` | 关闭归零UI，恢复正常显示 |

**逻辑状态与 UI 映射**：

| 当前数值区间 | 逻辑状态 | UI 表现 | 惩罚与引导 |
| --- | --- | --- | --- |
| = 0 | `STATE_DEPLETED` | 灰化归零态 | 归零惩罚与“去恢复”引导生效 |
| > 0 且 ≤ 警告阈值 | `STATE_RECOVERING` | 警告态（橙色条与警告反馈） | 归零惩罚和引导已解除；恢复加速仍可生效 |
| > 警告阈值 且 < 安全线 | `STATE_RECOVERING` | 正常视觉 | 无惩罚、无引导、无警告；仅内部继续记录恢复中 |
| ≥ 安全线 | `STATE_NORMAL` | 正常视觉 | 无 |

因此，警告 UI 在数值超过警告阈值后立即解除；安全线只用于结束内部的恢复加速和逻辑状态，不额外保留警告视觉。

**体力状态机**：

| 状态名 | 说明 | 转换条件 | 副作用 |
| --- | --- | --- | --- |
| `STAMINA_NORMAL` | 体力 \> 2 | 体力 ≤ 2 | 触发体力警告 |
| `STAMINA_LOW` | 体力 ≤ 2 且 \> 0 | 体力 \> 2 → NORMAL；体力 = 0 → DEPLETED | 警告UI |
| `STAMINA_DEPLETED` | 体力 = 0 | 体力 ≥ 1 → NORMAL | 阻止探索/战斗行动 |

### 4.7 离线指标处理

#### 4.7.1 离线结算流程

**触发条件**：玩家上线时

**处理时序**：

```
[玩家上线] → [读取上次离线时间] → [计算离线时长] → [结算补给离线消耗] → [结算耐久离线状态] → [结算体力离线恢复] → [检查归零/警告] → [弹出离线结算面板] → [玩家确认] → [数据写入]
```

**详细步骤**：

| 步骤 | 操作 | 数据变更 | 异常处理 |
| :---: | --- | --- | --- |
| 1 | 读取 `survival_status.last_online_time` | 无 | 数据不存在时跳过离线结算 |
| 2 | 计算离线时长 `offline_minutes = (now - last_online_time) / 60` | 无 | 不设 8 小时上限；时间异常时按 0 分钟处理 |
| 3 | 结算补给离线消耗 | `supply = max(1.0, supply - 0.3 × offline_minutes)` | 离线结算最低保留 1.0，不触发归零状态 |
| 4 | 耐久离线不损耗 | 无 | - |
| 5 | 若 `offline_recovery` 开启，结算体力离线恢复 | `stamina += floor(offline_minutes / recovery_interval_min)` | 截断至上限 |
| 6 | 检查指标阈值状态 | 更新 `status` 字段 | - |
| 7 | 弹出离线结算面板（显示消耗/恢复详情） | 无 | - |
| 8 | 玩家点击确认 | 写入最终数据 | - |

---

#### 4.7.2 离线消耗规则

**补给离线消耗**：

```
final_supply = max(OFFLINE_SUPPLY_MINIMUM, current_supply - offline_supply_rate × offline_minutes)
```

- 离线消耗速率为 0.3/分钟（在线 1.0/分钟 的 30%）
- 离线消耗不受环境修正影响（离线时环境不模拟）
- 离线时长不设上限，全部实际离线时间都参与结算
- `OFFLINE_SUPPLY_MINIMUM = 1.0`；离线结算不会将补给减至 0，因此不会仅因离线触发归零惩罚
- 被动休整与所有设施在离线期间仍停摆；最低补给保护不等同于离线恢复
- 离线收益的递减由离线收益系统独立结算：前 4 小时按 100% 收益；从第 5 小时起，每个完整离线小时的收益系数为上一小时的 90%（第 5 小时 90%、第 6 小时 81%，依此类推），不设停止累计时长

**离线收益递减接口（由离线收益系统实现）**：

```
hour_multiplier(hour_index) =
    1.0,                  hour_index <= 4
    0.9 ^ (hour_index-4), hour_index > 4
```

- `hour_index` 从离线开始后的第 1 个完整小时计数；不足 1 小时的尾段按其所属小时的系数按分钟比例结算。
- 生存系统只提供实际离线时长和补给结算结果，不计算、不保存离线生产收益。

**耐久离线状态**：

- 离线时耐久不自然损耗
- 离线时维修站不运转（不自动修复）
- 上线时耐久值保持离线前的值

## 六、数值公式

### 6.1 补给消耗公式

**公式**：

```
supply_decrement = base_supply_rate × (1 + modifier_sum) × (tick_interval / 60)
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `supply_decrement` | float | 本次 Tick 补给减少量 | 计算得出 |
| `base_supply_rate` | float | 基础消耗速率，在线 = 1.0/分钟，离线 = 0.3/分钟 | 配置表读取 |
| `modifier_sum` | float | 环境修正系数之和（加法叠加，上限 2.0） | 4.2 模块计算 |
| `tick_interval` | int | Tick 间隔秒数，默认 5 秒 | 配置表读取 |

**计算示例**：

> 在线状态，夜晚（修正+0.2），暴雨天气（修正+0.3），寒冷海域（修正+0.3）。
> modifier\_sum = 0.2 + 0.3 + 0.3 = 0.8
> supply\_decrement = 1.0 × (1 + 0.8) × (5 / 60) = 0.15
> 每 5 秒消耗 0.15 补给 = 1.8/分钟

---

### 6.2 耐久损耗公式

**公式**：

```
durability_decrement = base_durability_loss × (1 + durability_modifier_sum)
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `durability_decrement` | float | 本次事件耐久减少量 | 计算得出 |
| `base_durability_loss` | float | 基础损耗值（自然损耗/事件损耗） | 配置或事件参数 |
| `durability_modifier_sum` | float | 当前生效耐久修正系数之和；采用加法叠加并截断 | 生存系统 |

**自然损耗计算**：

```
natural_durability_loss = 0.5 × (1 + durability_modifier_sum) × (tick_interval / 3600)
```

> 每 5 秒 Tick 自然损耗 = 0.5 × (5/3600) = 0.000694（极低，可忽略不计）

**计算示例**：

> 当前 MVP 尚未启用天气或其他耐久修正，`durability_modifier_sum = 0`。
> Boss 战斗基础损耗 20。
> durability\_decrement = 20 × (1 + 0) = 20。
> 后续启用多个耐久修正时，例如 +0.3 和 +0.2：
> durability\_decrement = 20 × (1 + 0.3 + 0.2) = 30。

---

### 6.3 体力消耗与恢复公式

**体力消耗公式**：

```
stamina_decrement = cost_per_action × action_count
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `stamina_decrement` | int | 体力减少量 | 计算得出 |
| `cost_per_action` | int | 探索读取 `cost_per_explore`；进入战斗读取 `cost_per_battle` | `stamina_config` 读取 |
| `action_count` | int | 本次请求的行动数；探索和进入战斗均为 1 | 行为触发 |

> 战斗体力在 BattleSystem 创建 BattleState 前一次性预扣；战斗内回合、普通攻击与技能的 `action_count` 均为 0，不产生额外体力消耗。

**体力恢复公式**：

```
recovery_points = floor(elapsed_seconds / (recovery_interval_min × 60))
stamina = min(stamina + recovery_points, max_stamina)
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `recovery_points` | int | 恢复体力点数 | 计算得出 |
| `elapsed_seconds` | int | 经过秒数 | 时间戳差值 |
| `recovery_interval_min` | int | 恢复间隔（分钟），默认 15 | `stamina_config` 读取 |
| `max_stamina` | int | 体力上限 | `stamina_config` 读取 |

**计算示例**：

> 体力上限 10，当前体力 3，恢复间隔 15 分钟。
> 离线 1 小时 = 3600 秒。
> recovery\_points = floor(3600 / (15 × 60)) = floor(4.0) = 4
> stamina = min(3 + 4, 10) = 7

---

### 6.4 食物恢复公式

**公式**：

```
supply_recovery = food_item.recovery_amount × use_count
final_supply = min(current_supply + supply_recovery, MAX_SUPPLY)
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `supply_recovery` | int | 补给恢复总量 | 计算得出 |
| `food_item.recovery_amount` | int | 单个食物恢复量 | `food_item_config` 读取 |
| `use_count` | int | 使用数量（通常为 1） | 玩家操作 |
| `current_supply` | float | 当前补给值 | `survival_status` 读取 |
| `MAX_SUPPLY` | int | 补给上限（100） | 常量 |

**被动休整与设施恢复速率**：

```
passive_recovery_per_min = passive_recovery_rate × acceleration_multiplier
```

| 恢复来源 | 恢复速率 | 恢复指标 | 触发条件 | 备注 |
| --- | :---: | :---: | --- | --- |
| 被动休整 | +0.5/分钟 | 补给 | 在线自动 | 无需设施，船员自然休息 |
| 被动休整（归零加速） | +1.5/分钟 | 补给 | 补给 \< 10 时自动触发 | ×3 倍率，补给 ≥ 10 后恢复 |
| 手动进食（烤鱼） | +15/次 | 补给 | 玩家手动 | 需厨房产出食物 |
| 蒸馏器 | +10/分钟（按使用计算） | 补给 | 玩家手动饮用 | 需海水原料 |
| 维修站 | +3/分钟 | 耐久 | 在线自动 | 需木材原料 |
| 维修站（归零加速） | +6/分钟 | 耐久 | 耐久 \< 10 时触发 | ×2 倍率 |

---

### 6.5 设施与被动休整恢复公式

**公式**：

```
auto_recovery = recovery_rate × (tick_interval / 60) × acceleration_multiplier
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `auto_recovery` | float | 本次 Tick 自动恢复量 | 计算得出 |
| `recovery_rate` | float | 每分钟恢复速率 | 配置表读取 |
| `tick_interval` | int | Tick 间隔秒数 | 配置表读取 |
| `acceleration_multiplier` | float | 加速倍率（正常=1.0，被动休整归零=3.0，维修站归零=2.0） | 状态机判断 |

**计算示例**：

> 被动休整正常恢复，补给 = 50（非归零状态）。
> passive\_recovery = 0.5 × (5/60) × 1.0 = 0.0417
> 每 5 秒恢复约 0.042 补给 = 0.5/分钟
>
> 补给归零（= 0），被动休整归零加速 ×3。
> passive\_recovery = 0.5 × (5/60) × 3.0 = 0.125
> 每 5 秒恢复 0.125 补给 = 1.5/分钟
>
> 维修站正常运转，耐久 = 50（非归零状态）。
> auto\_recovery = 3 × (5/60) × 1.0 = 0.25
> 每 5 秒恢复 0.25 耐久 = 3/分钟
>
> 耐久归零（= 0），维修站归零加速。
> auto\_recovery = 3 × (5/60) × 2.0 = 0.5
> 每 5 秒恢复 0.5 耐久 = 6/分钟

---

### 6.6 警告阈值与惩罚

**阈值配置**：

| 指标 | 警告阈值 | 归零阈值 | 安全线 | 归零惩罚 |
| --- | :---: | :---: | :---: | --- |
| 补给 | ≤ 25 | = 0 | ≥ 30 | 手动操作效率 -50% |
| 耐久 | ≤ 30 | = 0 | ≥ 35 | 航速 -40%，无法战斗 |
| 体力 | ≤ 2 | = 0 | ≥ 3 | 无法探索/战斗 |

**效率惩罚计算**：

```
实际效率 = 基础效率 × (1 - penalty_rate)
```

| 归零指标 | penalty\_rate | 影响范围 |
| --- | :---: | --- |
| 补给归零 | 0.50 | 建造耗时 ×2、采集产出 ×0.5 |
| 耐久归零 | 0.40 | 航行速度 ×0.6 |
| 体力归零 | 1.00（行动锁定） | 探索/战斗不可用 |

---

### 6.7 离线消耗计算

**补给离线消耗公式**：

```
final_supply = max(offline_supply_minimum, current_supply - offline_supply_rate × offline_minutes)
```

**变量说明**：

| 变量 | 类型 | 说明 | 来源 |
| --- | --- | --- | --- |
| `final_supply` | float | 离线结算后的补给值 | 计算得出 |
| `offline_supply_rate` | float | 离线消耗速率（0.3/分钟） | 配置表读取 |
| `offline_minutes` | float | 离线时长（分钟） | 时间戳差值 |
| `offline_supply_minimum` | float | 离线补给下限（1.0） | `survival_config` 读取 |

**体力离线恢复公式**：

```
若 stamina_config.offline_recovery == true:
    offline_stamina_recovery = floor(offline_minutes / recovery_interval_min)
    final_stamina = min(stamina + offline_stamina_recovery, max_stamina)
否则:
    final_stamina = stamina（不变）
```

**计算示例**：

> 玩家满补给 100，离线 5 小时 = 300 分钟。
> final\_supply = max(1.0, 100 - 0.3 × 300) = 10。
> 上线时补给为 10，不触发归零。
>
> 若离线恢复开关开启，恢复间隔 15 分钟：
> 体力离线恢复 = floor(300 / 15) = 20
> 上线时体力 +20（截断至上限）。

**离线消耗节奏**：

| 离线时长 | 满补给结算后补给 | 归零状态 |
| --- | :---: | --- |
| 1 小时 | 82 | 不触发 |
| 4 小时 | 28 | 不触发 |
| 8 小时 | 1（下限保护） | 不触发 |
| 12 小时 | 1（下限保护） | 不触发 |

> *设计意图：离线补给可降至 1，但不会因为离线直接触发归零惩罚。被动休整与设施在离线时不产出；玩家上线后可通过被动休整、手动进食或维修设施恢复。离线收益的递减规则由离线收益系统独立结算，不改变上述补给公式。*
