## 一、文档概述

### 1.1 文档目标

本文档梳理《沧海余生》全部14个系统之间的关联关系，清晰展示：
- **数据流向**：哪个系统的产出是另一个系统的输入
- **依赖关系**：哪个系统必须先存在/初始化，另一个才能运转
- **交互方式**：系统间通过什么机制通信（直接调用/事件广播/共享数据/状态轮询）

程序组可据此文档规划模块划分、接口设计、初始化顺序和数据存储结构。

### 1.2 术语约定

| 术语 | 含义 |
|------|------|
| **生产者→消费者** | A系统产出数据/B系统消费数据的关系 |
| **强依赖** | B系统无法独立运转，必须A系统先就绪 |
| **弱依赖** | B系统可独立运转，但A系统提供的数据会增强B系统功能 |
| **事件订阅** | A系统广播事件，B系统监听并响应，A不感知B的存在 |
| **共享状态** | 多系统共同读写的全局数据（如玩家舰队状态） |
| **配置读取** | 系统从配置表读取静态参数，不产生运行时依赖 |

### 1.3 设计哲学回顾

| 原则 | 说明 | 对程序架构的影响 |
|------|------|-----------------|
| 中轻度泛用户 | 低门槛、归零不致死、无惩罚 | 不需要复杂的死亡/复活逻辑，降效即可 |
| 三合一玩法 | 模拟经营×卡牌构筑×大地图探险 | 三大玩法模块需要独立但可互调 |
| 可插拔社交 | L0-L4分级，核心不依赖社交 | 社交层必须接口化，不侵入核心循环 |
| 多平台 | Steam/小游戏/移动端 | 输入层抽象、UI自适应、存档可迁移 |
| 离线挂机 | 五项收益+衰减+结算 | 需要服务器时间戳、离线计算引擎 |

## 二、系统分层架构总览

### 2.1 四层架构

```
┌─────────────────────────────────────────────────────────────────────┐
│                        待设计层 (SYS-012~014)                        │
│           社交系统 · 叙事与任务系统 · 成就与图鉴系统                    │
│          （可插拔，不侵入核心循环，可后期接入）                         │
├─────────────────────────────────────────────────────────────────────┤
│                       进阶成长层 (SYS-008~011)                       │
│    伙伴卡牌系统 · 舰队系统 · 舰载设施与开场技能系统 · 离线挂机系统       │
│          （核心循环的成长引擎，提供持续目标和正反馈）                   │
├─────────────────────────────────────────────────────────────────────┤
│                       核心循环层 (SYS-004~007)                       │
│      探索与遭遇系统 · 战斗系统 · 建造与升级系统 · 资源管理与生产链       │
│          （游戏核心循环的四大支柱，驱动玩家行为）                      │
├─────────────────────────────────────────────────────────────────────┤
│                       底层基础层 (SYS-001~003)                       │
│          生存系统 · 经济与经营系统 · 天气与环境系统                     │
│          （全局基础服务，被上层系统读取和写入）                        │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 分层规则

| 层级 | 职责 | 依赖方向 | 初始化顺序 |
|------|------|----------|:--------:|
| **底层基础层** | 提供全局状态、基础约束和共享环境数据 | 被上层依赖，自身不依赖上层 | 最先初始化 |
| **核心循环层** | 驱动核心玩法循环（探索→收集→建造→战斗→成长） | 依赖底层，被进阶层调用 | 第二初始化 |
| **进阶成长层** | 提供成长深度和长线目标 | 依赖核心循环和底层 | 第三初始化 |
| **待设计层** | 扩展功能，不影响核心循环 | 可选依赖任何已就绪系统 | 最后/按需初始化 |

> **关键原则**：上层可以调用下层，下层不直接调用上层。下层需要通知上层时，通过**事件广播**机制实现解耦。

## 三、14个系统功能概述

### 3.1 底层基础层

#### SYS-001 生存系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 维护玩家生存状态（补给、耐久、体力），提供生存压力但不构成挫败 |
| **功能概述** | 双指标（补给100/耐久100）+体力行动资源；环境修正叠加层（昼夜/天气/海域温度/行动消耗）；归零不致死仅降效；被动休整恢复+0.5/分钟作为安全网；厨房生产食物、维修站恢复耐久 |
| **架构作用** | 全局约束层——所有玩家行为消耗生存资源，所有设施产出恢复生存资源。是核心循环的"节奏调节器" |
| **对外提供** | `Supply`（补给值）、`Durability`（耐久值）、`Stamina`（体力值）、`EfficiencyModifier`（效率修正系数） |
| **依赖系统** | SYS-003（读取天气环境修正）、SYS-006（读取设施数据计算自动恢复）、SYS-004/005/006（接收行为消耗事件） |

#### SYS-002 经济与经营系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 维护游戏内货币体系、交易机制和人口管理 |
| **功能概述** | 三种货币（贝壳币/零件券/声望）；交易所（浮动价格机制、连续出售递减）；以物易物（NPC商船）；人口管理（招募上限=旗舰床铺数、出战位3个、派驻位） |
| **架构作用** | 经济循环引擎——将资源转化为货币、将货币转化为稀缺物资，驱动玩家参与交易和探索 |
| **对外提供** | `ShellCoins`、`PartVouchers`、`Reputation`、`TradePriceModifier`（浮动价格系数）、`PopulationCap`（人口上限） |
| **依赖系统** | SYS-007（读取资源库存计算交易）、SYS-008（读取床铺数计算人口上限）、SYS-004（贸易点触发交易）、SYS-005（Boss掉落贝壳币） |

#### SYS-003 天气与环境系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 维护全局环境状态（昼夜、天气、海域温度），为多系统提供环境修正参数 |
| **功能概述** | 昼夜循环（影响视野和修正系数）；天气状态（晴/阴/雨/暴风/雾，影响航行和生存消耗）；海域温度（影响环境修正叠加）；环境修正采用加法叠加，上限2.0 |
| **架构作用** | 全局环境数据源——被生存系统、探索系统、战斗系统共享读取，是"动态世界感"的数据基础 |
| **对外提供** | `TimeOfDay`（时段）、`WeatherType`（天气类型）、`SeaTemperature`（海域温度）、`EnvironmentModifier`（综合环境修正系数） |
| **依赖系统** | 独立运转（按时间轴自行演化），不依赖其他系统。但SYS-004可触发局部天气事件（如暴风雨遭遇） |

### 3.2 核心循环层

#### SYS-004 探索与遭遇系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 驱动大地图探索、触发遭遇事件、管理在线拾荒节奏 |
| **功能概述** | 六边形格大地图（迷雾机制、海域类型、特殊格子）；四类遭遇事件（资源40%/救援25%/战斗25%/叙事10%）；碎片潮汐（每2-3分钟，四种潮汐类型）；巡游威胁（每15-30分钟，3秒快速决策）；水下探索（4×4网格+10格空气限制）；钩索升级系统 |
| **架构作用** | 核心循环引擎——"探索"是一切行为的起点，产生资源、伙伴、战斗机会和叙事内容 |
| **对外提供** | `MapData`（地图状态）、`EncounterResult`（遭遇结果）、`TideEvent`（潮汐事件）、`ThreatEvent`（威胁事件）、`FleetPosition`（舰队位置） |
| **依赖系统** | SYS-001（消耗补给/体力、读取耐久判断能否战斗）、SYS-003（读取天气影响航行）、SYS-009（读取舰队速度计算移动消耗）、SYS-007（产出资源入库）、SYS-008（救援事件招募伙伴）、SYS-005（战斗事件触发战斗） |

#### SYS-005 战斗系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 管理双阶段Boss战斗流程，结算战斗奖励 |
| **功能概述** | 双阶段战斗（Phase 1开场技能自动释放→Phase 2卡牌回合制）；Boss行为模式（可预见→可应对，固定模板+弱点机制）；回合制核心（3伙伴出战、能量点系统、速度排序）；战斗失败仅扣耐久不丢进度；战斗奖励（基础掉落+首杀奖励） |
| **架构作用** | 核心循环的验证节点——验证建造成果（开场技能）和伙伴养成（卡牌战斗），产出稀有材料驱动成长 |
| **对外提供** | `BattleResult`（战斗结果：胜利/失败）、`BattleDamage`（舰队/伙伴伤害）、`DropItems`（掉落物品列表）、`PartnerExp`（伙伴经验） |
| **依赖系统** | SYS-010（读取舰载设施数据计算开场技能）、SYS-008（读取伙伴属性/技能/编队）、SYS-001（消耗体力、耐久）、SYS-007（掉落入库）、SYS-009（读取舰队耐久计算战斗失败惩罚） |

#### SYS-006 建造与升级系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 管理船只网格建造、船型升级、逐格扩展和设施放置 |
| **功能概述** | 10级船型体系（3×3→10×12）；逐格扩展（旗舰逐格/支援船一键，仅消耗扩展点无材料成本）；设施分类（生存/生产/储存/舰载武器/舰载防御/舰载辅助/生活/特殊）；研究台双轨解锁（等级解锁类别权限+研究台解锁具体配方）；建造规则（邻接/限一/拆除返还50%/移动免费） |
| **架构作用** | 核心循环的建造引擎——将资源转化为设施，设施同时驱动生存恢复、生产效率和战斗力 |
| **对外提供** | `ShipGrid`（船只网格状态）、`FacilityList`（设施列表及等级）、`ExpansionPoints`（扩展点数）、`ResearchProgress`（研究进度）、`ShipLevel`（船型等级） |
| **依赖系统** | SYS-007（消耗资源建造/升级）、SYS-009（读取船只列表确定建造目标）、SYS-001（写入设施恢复参数）、SYS-007（写入生产设施产出参数）、SYS-010（写入舰载设施数据）、SYS-011（写入设施数据计算离线产出） |

#### SYS-007 资源管理与生产链系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 管理全舰队共享仓库、资源加工链和自动化生产 |
| **功能概述** | 五类资源（基础/加工/稀有/食物/货币）；完整生产链（漂浮物→基础资源→加工资源→高级建造）；自动化三档（手动100%/伙伴托管80%/AI基础50%）；共享仓库+本地缓存；储存上限受设施影响 |
| **架构作用** | 核心循环的资源枢纽——所有系统的资源产出和消耗都经过此系统 |
| **对外提供** | `Inventory`（全舰队库存）、`ProductionLine`（生产线状态）、`StorageCap`（储存上限）、`ResourceType`（资源类型枚举） |
| **依赖系统** | SYS-004（接收探索/潮汐产出）、SYS-005（接收战斗掉落）、SYS-006（提供建造/升级消耗）、SYS-002（提供交易库存）、SYS-008（读取派驻伙伴计算生产效率）、SYS-011（提供离线产出基础数据） |

### 3.3 进阶成长层

#### SYS-008 伙伴卡牌系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 管理伙伴招募、养成、编队和派驻 |
| **功能概述** | 五种定位（收集/建造/战斗/守护/支援）；卡牌养成（Lv.1-20等级、好感度1-10、Lv.10突破）；组合加成（双人拾荒/攻守一体/全能船队/老友重逢/孤胆英雄）；派驻系统（未出战伙伴派驻设施提高效率）；个人故事事件 |
| **架构作用** | 成长深度引擎——伙伴是"可养成的卡牌棋子"，连接日常活动（派驻）和战斗（出战），是玩家情感投入的核心载体 |
| **对外提供** | `PartnerList`（伙伴列表及属性）、`BattleTeam`（出战编队）、`DispatchAssignment`（派驻分配）、`PartnerExp`（伙伴经验）、`ComboBonus`（组合加成） |
| **依赖系统** | SYS-004（救援事件→招募）、SYS-005（战斗→经验/好感度）、SYS-006（读取床铺数→招募上限）、SYS-007（派驻→设施效率加成）、SYS-011（离线→伙伴经验）、SYS-002（人口管理） |

#### SYS-009 舰队系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 管理多船舰队的编成、航行和扩展资格 |
| **功能概述** | 舰队结构（1旗舰+N支援船）；旗舰不可摧毁/支援船可退役；建造资源递增（第5艘起指数增长）；舰队统一航行（速度=最慢船）；舰队共享仓库；独立耐久系统；MVP不派驻伙伴（后续迭代加船长任命） |
| **架构作用** | 容器管理层——为建造系统提供船只单元、为战斗系统提供舰队编成、为探索系统提供航行能力 |
| **对外提供** | `FleetComposition`（舰队编成）、`ShipList`（船只列表及状态）、`FleetSpeed`（舰队速度）、`FleetDurability`（舰队总耐久）、`ShipUnlockProgress`（解锁进度） |
| **依赖系统** | SYS-006（读取船只等级/网格状态判断解锁资格）、SYS-001（写入舰队耐久）、SYS-004（提供航行速度数据）、SYS-005（提供舰队耐久计算战斗失败惩罚）、SYS-007（共享仓库管理）、SYS-010（提供船只列表汇总开场技能） |

#### SYS-010 舰载设施与开场技能系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 管理舰载武器/防御/辅助设施，在Boss战开场自动释放技能 |
| **功能概述** | 8种舰载设施（炮台/导弹架/鱼雷管/护盾发生器/重装甲板/雷达站/引擎增压器/修理无人机）；开场技能自动释放（辅助→防御→武器顺序）；按设施类型独立结算；同类可叠加（多炮台=更猛齐射）；设施等级与船等级独立 |
| **架构作用** | 建设→战斗的桥梁——建造系统的产出直接转化为战斗力演出，是"造更多炮台=开场更强"的核心体验 |
| **对外提供** | `OpeningSkillResult`（开场技能结算结果：伤害/护盾/增益/减益）、`FacilityCombatData`（设施战斗数据）、`FleetFirePower`（舰队总战力） |
| **依赖系统** | SYS-006（读取舰载设施数量/等级/类型）、SYS-009（读取舰队所有船只的设施配置）、SYS-005（输出开场技能结果→影响战斗初始状态） |

#### SYS-011 离线挂机收益系统

| 维度 | 说明 |
|------|------|
| **核心职责** | 管理玩家离线期间的自动收益和上线结算 |
| **功能概述** | 五项收益（基础物资/食物补给/加工产物/伙伴经验/贝壳币）；离线系数0.50×(1+装饰品加成)，上限0.625；4小时全效+衰减（4-8小时每多1小时-10%，8小时封顶50%）；上线结算动画（五项依次弹出，0.5秒间隔）；特殊情况处理（耐久归零/补给耗尽/连续7天未上线） |
| **架构作用** | 在线/离线桥梁——确保"回来总有惊喜"，制造上线理由，不替代在线游玩 |
| **对外提供** | `OfflineReport`（离线收益报告）、`OfflineDuration`（离线时长）、`OfflineEfficiency`（离线效率系数） |
| **依赖系统** | SYS-006（读取设施数量/类型→计算产出）、SYS-008（读取伙伴数量→计算经验）、SYS-001（读取补给/耐久状态→判断设施是否运转）、SYS-007（写入离线产出资源）、SYS-002（写入贝壳币） |

### 3.4 待设计层

#### SYS-012 社交系统

### 5.2 生存约束链路

```
SYS-003 天气系统
  │
  ├── 昼夜修正 → (+0.1~+0.3)

  │
  ├── 补给消耗 = 基础消耗(1/分钟) × 环境修正
  ├── 耐久消耗 = 基础消耗(0.5/小时) + 事件消耗
  ├── 体力消耗 = 按行动配置表固定值
  │
  ├── 恢复来源（由SYS-006建造系统写入）
  │   ├── 厨房 → 产食物 → 手动食用 → +补给
  │   ├── 蒸馏器 → 产淡水 → 手动饮用 → +补给
  │   ├── 维修站 → 自动恢复 → +耐久

  │
  ├── 归零保护
  │   ├── 补给=0 → 操作效率-50%（不致死）
  │   ├── 耐久=0 → 航行速度-40%+无法战斗（不致死）
  │   └── 补给=0时 → 被动休整×3加速（+1.5/分钟，无需设施）
  │
  └── 输出效率修正
      ├── → SYS-004 探索（低补给→拾取效率-50%）
      ├── → SYS-005 战斗（低耐久→无法进入战斗）
      └── → SYS-006 建造（低体力→建造速度降低）
```

### 6.2 强依赖关系清单

以下关系表示"B系统无法独立运转，必须A系统先就绪"：

| A系统（前置） | B系统（后置） | 依赖原因 |
|-------------|-------------|----------|
| SYS-001 生存 | SYS-004 探索 | 探索需要读取补给/耐久/体力状态判断是否可执行 |
| SYS-001 生存 | SYS-005 战斗 | 战斗需要读取体力判断行动、读取耐久判断可否进入 |
| SYS-003 天气 | SYS-001 生存 | 生存系统环境修正依赖天气数据（但可降级为默认值） |
| SYS-006 建造 | SYS-010 舰载设施 | 舰载设施数据来自建造系统的设施配置 |
| SYS-006 建造 | SYS-011 离线 | 离线产出依赖设施数量/类型 |
| SYS-007 资源 | SYS-006 建造 | 建造需要读取资源库存判断是否可执行 |
| SYS-008 伙伴 | SYS-005 战斗 | 战斗需要出战编队的伙伴属性/技能 |
| SYS-009 舰队 | SYS-010 舰载设施 | 开场技能需要汇总全舰队设施 |
| SYS-010 舰载设施 | SYS-005 战斗 | 开场技能结果是战斗Phase 1的输入 |

### 8.3 事件总线设计建议

```typescript
/**
 * 全局事件总线——所有系统间通信的核心枢纽
 * 设计原则：
 * 1. 生产者只负责广播事件，不关心谁监听
 * 2. 消费者只负责订阅事件，不关心谁产生
 * 3. 事件携带完整数据，消费者无需回查生产者
 * 4. 事件分同步和异步两种（战斗内事件同步，跨系统事件异步）
 */
class EventBus {
  // 同步事件（立即执行，用于战斗内、建造内等紧耦合场景）
  emitSync<T>(event: string, data: T): void;
  onSync<T>(event: string, handler: (data: T) => void): void;

  // 异步事件（下一帧执行，用于跨系统通信）
  emit<T>(event: string, data: T): void;
  on<T>(event: string, handler: (data: T) => void): void;
  off(event: string, handler: Function): void;
}

/**
 * 关键事件路由表
 */
const EventRoutes = {
  // 探索→战斗
  'explore.encounter.combat': ['battle.start'],

  // 探索→资源
  'explore.tide.complete': ['resource.add'],
  'explore.underwater.complete': ['resource.add'],
  'explore.encounter.resource': ['resource.add'],

  // 探索→伙伴
  'explore.encounter.rescue': ['partner.recruit'],

  // 战斗→资源/伙伴/舰队
```
